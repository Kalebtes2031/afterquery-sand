## 🚀 Verification & Upload Workflow

> **Follow the full [Expert pre-submission procedure](#-expert-pre-submission-procedure-follow-for-every-task) before every upload or resubmit.**

### 1. Local Multi-Tiered Verification (Fast, No Docker / Harbor Required)

Instead of relying on Harbor locally (which requires a local Docker daemon, nested virtualization, and can take 5–10 minutes per run while hiding low-CPU race conditions), use this **Local Multi-Tiered Verification Method**. It directly validates the 4 exact failure points evaluated by the platform verifier:

#### Tier 1: Patch Applicability & Hunk Verification

Ensure `source_patch.diff` applies cleanly with zero conflicts, zero fuzz, and valid LF endings against the broken repository base:

```bash
cd task-N/environment/app
git apply --check --verbose ../../solution/patches/source_patch.diff   # Must exit 0 with clean output
```

> [!IMPORTANT]
> If regenerating the patch, always use Python to avoid PowerShell UTF-16 / BOM corruption:
>
> ```bash
> python -c "import subprocess; open('../../solution/patches/source_patch.diff','wb').write(subprocess.run(['git','diff'],capture_output=True).stdout)"
> ```

#### Tier 2: Sequential State & Assertion Simulation (Node.js Script)

Simulate the platform's sequential test execution against the backend data store to detect state leakage, count desyncs, and contract failures:

1. **Model the Platform Execution Sequence**:
   The platform runs all tests in `behavior.spec.js` in a single run: `[P2P]` tests execute first, followed by `[F2P][D1]` through `[F2P][D6]`.
2. **Dual-Pass Verification**:
   - **Baseline Pass (`nop = 0`)**: Run the simulation with broken base code. Verify that all 6 `[Dn]` tests fail and both `[P2P]` tests pass.
   - **Solution Pass (`oracle = 1`)**: Run the simulation with patched code. Verify that 100% of the 6 `[Dn]` tests and both `[P2P]` tests pass cleanly.
3. **Audit Shared State Accumulation**:
   When `[P2P]` creates new records (e.g., creating an incident or adding an API key), in-memory counters increment (e.g. from 4 to 5). Assertions in subsequent `[F2P]` tests must check range bounds (`expect(activeCount).toBeGreaterThanOrEqual(4)`) rather than rigid equality (`toBe(4)`).

#### Tier 3: Spec Timing & Actionability Audit (Playwright Container Hardening)

Containers on the Sand evaluation platform run with strict 2-vCPU limits. Audit `tests/behavior.spec.js` for common container-level failure modes:

- **Zero Arbitrary Sleeps**: Never use `await page.waitForTimeout(400)`. Always synchronize actions with network responses:

  ```javascript
  // ❌ Fragile under container CPU contention:
  await page.click("#btn-action");
  await page.waitForTimeout(500);
  await page.reload();

  // ✅ Deterministic network synchronization:
  await Promise.all([
    page.waitForResponse(
      (resp) => resp.url().includes("/api/action") && resp.status() === 200,
    ),
    page.click("#btn-action"),
  ]);
  await page.reload();
  ```

- **Z-Index & Stacking Contexts**: Open modals or detail drawers (`z-index: 20`) must never obscure action buttons. Ensure action headers have `position: relative; z-index: 25;`.
- **Viewport Resilience & Overflow**: Playwright runs at 1280×720 by default. Ensure table containers use `overflow-x: auto` so action buttons are clickable without being clipped or hidden via `display: none`.
- **Input Cleaning**: Always clear inputs before typing (`await page.fill('#input', '')`) to avoid unintended text concatenation.

#### Tier 4: Verifier Parser & Reward Contract Check

Verify that test titles and counts perfectly match the platform verifier contract:

- Exactly 6 `[D1]` through `[D6]` defect tags + 2 `[P2P]` tags in `tests/behavior.spec.js`.
- Tag counts strictly match `fail_to_pass_count = 6` and `pass_to_pass_count = 2` in `task.toml`.
- Regex in `tests/parser.py` correctly extracts all 8 test names from test runner output.
- `tests/VERIFIER_EXPLANATION.md` is present and summarizes all 8 tests.

_(Optional Note: If local Docker is available, you may also run `harbor run -p ./task-N -a nop` and `harbor run -p ./task-N -a oracle` as a secondary containerized smoke test)._

## 🧭 Platform review pipeline (what a task must pass)

Real platform order from returned packages (e.g. `task-5.zip` / `sandwich-5225e6d6-…`). A task can pass **everything** below and still get **Returned for edits** if the last automated gate fails.

| Step                         | Meaning                                                |
| :--------------------------- | :----------------------------------------------------- |
| Intake checks                | Package accepted into the pipeline                     |
| Originality check            | Not a near-duplicate of an existing task               |
| Structure check              | Matches official template layout                       |
| Build                        | Environment / app builds                               |
| Change check                 | Meaningful broken→fixed delta                          |
| Writing check                | `instruction.md` is specific and human (not scaffold)  |
| Verification review          | Verifier wiring looks valid                            |
| Package check                | Archive contents / modes / assets OK                   |
| Baseline test run (`nop`)    | Broken base → reward `0`                               |
| Solution test run (`oracle`) | Reference patch → reward `1`                           |
| **Difficulty calibration**   | Frontier models must **not** solve it too consistently |
| Human review                 | Reviewer approval                                      |
| Final processing             | Approved / paid                                        |

> **Critical:** Passing structure, writing, baseline, and oracle is **not** enough. Difficulty calibration is the gate that most often returns otherwise-valid tasks.

## ✅ Expert pre-submission procedure (follow for every task)

> **Do not upload until every gate below is green.** Blind resubmits (repack only, reword only, or “hope it passes”) risk a project ban. Match the procedure to the **actual return reason** — if human review asked for two instruction fixes, do not rewrite the whole task.

### Step 0 — Identify what failed

| Return reason                 | Fix scope                                                | Do **not** do                                    |
| :---------------------------- | :------------------------------------------------------- | :----------------------------------------------- |
| Import / compare to template  | Package layout, git base, patch validity                 | Change difficulty or tests unless patch is wrong |
| Writing / scaffold language   | Rewrite `instruction.md` only                            | Repack without rewriting                         |
| Oracle reward 0               | Broken base, patch, or test order                        | Resubmit same archive                            |
| Difficulty calibration        | Deepen bugs + tighten tests + symptoms-only instructions | Instruction-only tweak                           |
| Human review (specific items) | Only listed items (e.g. screenshot paths, verifier doc)  | Add folders that break import                    |

### Step 1 — Package & import (Gate: Intake + Structure)

Run these **before** any upload. If import fails, nothing else runs.

- [ ] **Flat template layout** at archive root: `instruction.md`, `task.toml`, `launch.sh`, `environment/`, `tests/`, `solution/` — no extra top-level folders (`reference/`, `_patchtest/`, `test-results/`, etc.).
- [ ] **`environment/app/.gitkeep`** present.
- [ ] **`environment/problem_assets/broken.png`** and **`target.png`** present.
- [ ] **Git base inside app only** (not the monorepo root):
  ```bash
  cd task-N/environment/app
  # Ensure .gitignore excludes node_modules if you init here
  git init && git add -A && git commit -m "Base commit for <app> task"
  ```
- [ ] **`task.toml` → `base_commit = "HEAD"`** (never a Windows-only hash from `git rev-parse` on your machine — Sand re-inits on Linux and HEAD must match).
- [ ] **`source_patch.diff` applies cleanly** on broken base:
  ```bash
  git apply --check ../../solution/patches/source_patch.diff   # exit 0
  ```
- [ ] **Patch generated from `git diff`**, not hand-edited (UTF-8, LF; on Windows use Python redirect, not PowerShell `>` which can corrupt encoding).
- [ ] **No junk in archive**: no `node_modules/`, `test-results/`, `package-lock.json` bloat if avoidable, no nested `.git/` from app (ignored by pack, but do not commit node_modules into app git).

**Archive verify script** (run after every pack):

```bash
python -c "
import tarfile, sys
path = sys.argv[1]
t = tarfile.open(path)
names = set(t.getnames())
files = [n for n in names if not n.endswith('/')]
print('file count:', len(files))
required = [
  'instruction.md', 'task.toml', 'launch.sh',
  'environment/app/.gitkeep',
  'environment/problem_assets/broken.png',
  'environment/problem_assets/target.png',
  'solution/patches/source_patch.diff',
  'solution/solve.sh',
  'tests/behavior.spec.js',
  'tests/test.sh',
]
for p in required:
    print(p, 'OK' if p in names else 'MISSING')
bad = [n for n in names if 'node_modules' in n or n.startswith('reference/')]
print('BAD entries:', bad if bad else 'none')
" name-task-N.tar.gz
```

**Pack command** (always):

```bash
python pack_task.py ./task-N {name}-task-N.zip
```

### Step 3 — Tests & broken base (Gate: Baseline `nop`)

- [ ] **Exactly 6 × `[F2P]` + 2 × `[P2P]`** in `tests/behavior.spec.js`; titles must match platform parser exactly.

### Step 4 — Reference solution (Gate: Oracle)

Validate both `nop` (baseline fails all 6 F2P) and `oracle` (solution passes all 6 F2P + 2 P2P) using the local simulation workflow or Harbor:

#### Primary: Local Simulation (No Docker Required)

1. **Verify Patch Cleanliness**:
   ```bash
   cd task-N/environment/app
   git apply --check --verbose ../../solution/patches/source_patch.diff   # Must exit 0
   ```
2. **Run Node Simulation Script**:
   - Verify baseline outputs: all 6 `[Dn]` defects fail, 2 `[P2P]` pass (`reward = 0`).
   - Verify patched outputs: all 6 `[Dn]` defects pass, 2 `[P2P]` pass (`reward = 1`).
3. **Audit Shared In-Memory State**:
   - Check whether `[P2P]` creating new records changes metrics (e.g. `activeCount` increasing from 4 to 5). Relax exact equality assertions to range bounds (e.g. `toBeGreaterThanOrEqual(4)`).

#### Alternative: Harbor Verification (If Docker is Available)

```bash
harbor run -p ./task-N -a nop     # reward MUST be 0
harbor run -p ./task-N -a oracle  # reward MUST be 1
```

- [ ] **`nop = 0`** — broken base fails all `[F2P]`, passes all `[P2P]`.
- [ ] **`oracle = 1`** — patch fixes every `[F2P]` without breaking `[P2P]`.
- [ ] **Regenerate patch** after any broken-base change:
  ```bash
  cd environment/app
  git checkout .                    # restore broken
  # apply full fix, then:
  git diff > ../../solution/patches/source_patch.diff
  git checkout .                    # leave tree broken for pack
  git apply --check ../../solution/patches/source_patch.diff
  ```

## ⚠️ Common QA Failures (Lessons from Tasks 1–7 + human review)

These are real errors we hit during submission. The procedure above maps to each; details below.

### Pre-submit checklist (quick scan)

| Check                                                        | Why it matters                                                       |
| :----------------------------------------------------------- | :------------------------------------------------------------------- |
| `git init` + commit in `environment/app/`                    | Import validation expects a git base                                 |
| **`base_commit = "HEAD"`** in `task.toml`                    | Fixed hash from Windows fails Sand Linux re-init (tasks 1, 10)       |
| `environment/app/.gitkeep` present                           | Missing file causes **import failure** (task-5)                      |
| **No root `reference/` folder**                              | Breaks template import (task-4); use `tests/VERIFIER_EXPLANATION.md` |
| `source_patch.diff` passes `git apply --check`               | Hand-written or stale patches → corrupt patch / import rejection     |
| Patch generated from `git diff` on broken base               | Never ship unverified hand-edited hunks                              |
| `[P2P]` before stateful `[F2P]`                              | Oracle reward 0 when tests mutate shared state (task-3, 7)           |
| Multi-tiered simulation (`nop=0`, `oracle=1`)                | Solution failure = reference solution does not pass tests            |
| `instruction.md` specific, not template text                 | Writing check rejects scaffold (tasks 1, 8)                          |
| **Screenshot paths: `broken.png` / `target.png` only**       | `/app/problem_assets/` leaks app dir (task-4 human review)           |
| Instructions = **symptoms**, not algorithm                   | Difficulty calibration fail (tasks 5, 7)                             |
| `broken.png` + `target.png` in `environment/problem_assets/` | Required assets                                                      |
| Pack with `pack_task.py`                                     | Unix permissions, LF, directory entries                              |
| No `node_modules` / test artifacts in archive                | Bloated pack; import issues                                          |
| No `DEFECT` / `BUG` comments in source                       | Leaks fix; desyncs patch                                             |
| Defects deep / multi-module (`Fail site ≠ Fix site`)         | Shallow bugs fail difficulty (tasks 5, 7)                            |

### Failure 1: Import rejected — _"Compare it with the task template"_ (tasks 1, 5, 10, 4)

**Symptoms:** Package never imports; no further checks run.

**Root causes we found:**

1. **`base_commit` is a literal hash** that does not equal Sand’s fresh `HEAD` after re-init — use **`"HEAD"`**.
2. **Corrupt `source_patch.diff`** — hand-edited or UTF-16 from PowerShell redirect.
3. **Missing `environment/app/.gitkeep`**.
4. **Extra root folders** (e.g. `reference/`) not in template.
5. **Bad tar layout** — pack without `pack_task.py` missing directory entries.
6. **No git repo** in `environment/app/` when platform validates base.

**Fix workflow:**

```bash
cd task-N/environment/app
git init && git add -A && git commit -m "Base commit"
git apply --check ../../solution/patches/source_patch.diff   # must exit 0

# Regenerate patch (Python for UTF-8 on Windows):
python -c "import subprocess; open('../../solution/patches/source_patch.diff','wb').write(subprocess.run(['git','diff'],capture_output=True).stdout)"
```

### Failure 3: Oracle — _"Reference solution did not pass your own tests (reward 0)"_ (tasks 3, 4, 12, 13)

**Symptoms:** Import/writing pass; solution run scores 0.

**Root causes identified across tasks:**

1. **State Leakage from Early Tests (Task 4)**:
   - When `[P2P]` runs first and creates a new entity, in-memory active counts increase (e.g. from 4 to 5).
   - Hardcoded assertions like `expect(activeCount).toBe(4)` in later `[F2P][D2]` tests will fail with `Expected: 4, Received: 5`.
   - **Fix**: Use boundary assertions like `expect(activeCount).toBeGreaterThanOrEqual(4)` while still checking non-NaN finite values.
2. **Fixed Timeouts & Network Race Conditions (Tasks 4, 10)**:
   - Tests using `await page.waitForTimeout(400)` or `500` before `page.reload()` race with slow server writes in 2-CPU Docker containers.
   - **Fix**: Use `await Promise.all([page.waitForResponse(r => r.url().includes('...') && r.status() === 200), button.click()])`.
3. **Action Interception by Overlays / Drawers (Tasks 12, 13)**:
   - Open detail drawers (`z-index: 20`) covering top action bars (`z-index: 0`), causing Playwright click timeouts.
   - **Fix**: Set `position: relative; z-index: 25;` on `.top-actions`.
4. **Test order poisoning**:
   - Stateful F2P running before P2P or deleting shared seed records needed by later tests.
5. **Stale patch / broken base desync**:
   - Patch does not apply cleanly (`git apply --check` fails).

**Fix:** Run the [Local Multi-Tiered Verification Workflow](#1-multi-tiered-verification-fast-no-docker--harbor-required); verify patch applies cleanly; check state accumulation; synchronize network responses; then repack.
